# UX Optimization Spec

> 编写：2026-11-27。读者是执行优化的 Agent。文中行号对应编写时的 `main`（`8da1c5f`），动手前以实际代码为准。

## 1. 目标

好影的视觉风格已经成型，问题在使用体验：“随心一刷”拖动卡顿、只能拖不能点；页面上有几处看不清、点不动、说的和做的不一致的地方。本轮在不改变视觉风格的前提下，把这些地方补到一个完整产品该有的水平。

## 2. 范围与约束

**做**：随心一刷性能、随心一刷交互、页面与内容三组，共 29 项（第 4 节）。

**不做**：
- 不新增密钥、环境变量、外部服务，不改部署配置。
- 不启用登录和云端同步（需要 Supabase 配置）。
- 不接真实预告片，不改后端推荐和片库逻辑，不改 Vibe 的提示词与接口。
- 不重构 `App.tsx` 的整体结构，只做条目需要的拆分。

**风格原则**：配色、字体、圆角、玻璃质感、日夜两套渐变背景保持不变。新增控件复用现有的 class 和 `index.css` 里的变量，尺寸和间距向同页面已有控件看齐。拿不准时，改完与改前的截图并排放，整体观感应当认不出是两个版本。

**工作方式**：
- 从 `main` 建分支 `feat/ux-optimization`。不推送 `main`（Netlify 和 Render 很可能随 `main` 自动上线），不部署。
- 本机有提交格式 hook，可能拦截不带工单号的提交。被拦时不要绕过，把“暂存、提交、推送分支”写成一条命令交给用户执行。
- 删除任何文件前列出清单请用户确认。
- 本地运行：`npm run dev`（端口 3000）即可。没有后端时前端会用 `public/tmdb-movies-cache.json` 的静态片库，本轮的条目都能在这种状态下验证。Vibe 推荐需要后端和密钥，不在验证范围，只要求类型检查和构建通过、界面能打开。

## 3. 已确认的现状

线上 1512×794 窗口实测，加代码阅读：

- 随心一刷同时渲染 4 张卡片，每张都带 40px 背景模糊；页面外框是 1280×1059 的 24px 背景模糊，底下有三个 140–160px 模糊的大光斑，其中两个在持续做动画。
- 卡片高 600px，一屏放不下，要滚动才能看到底部的操作提示；提示颜色很淡。
- 只能拖动，没有按钮，键盘无效。
- 详情弹窗按 Esc 关不掉。
- 日间主题下，侧栏的类型、“最近添加”、“暂无观看记录”和页脚文字压在浅紫和粉色上，几乎看不清。
- “观看预告片”播放的是与电影无关的占位视频。

拖动帧率和手机端没有实测数据，由本轮补上（P0、U12）。

## 4. 条目

每项格式：问题 → 想要的效果 → 验收标准。

### P. 随心一刷性能

**P0 先建立基线**
- 做法：写一段页面内采样脚本（`requestAnimationFrame` 帧间隔加 `PerformanceObserver` 的 `longtask`），在标签页可见的前提下，连续拖动切换 10 张卡片，记录平均帧间隔、p95 帧间隔、超过 50ms 的长任务数。工具支持时加 4 倍 CPU 降速再测一组。改动前后用同一套步骤。
- 验收：收尾说明里有改前、改后两组数字。目标是改后 p95 帧间隔不超过 33ms、长任务数为 0（4 倍降速下）。达不到时写明剩余瓶颈在哪里，不能只写“已优化”。

**P1 卡片上的背景模糊**
- 问题：`TinderSwipeDeck.tsx:280-281` 每张卡片 `backdropFilter: blur(40px)`，而卡片底色不透明度 0.94–0.98，模糊几乎看不出来，却要每帧重算。
- 效果：去掉卡片上的背景模糊。
- 验收：改前改后同一张卡片的截图并排看不出差别；页面里带背景模糊的卡片元素数为 0。

**P2 外框模糊叠加动画光斑**
- 问题：外框 `App.tsx:633-646` 的 24px 背景模糊覆盖整页，底下 `App.tsx:622-630` 的光斑用 `animate-pulse-slow`（`index.css` 的 `slow-pulse`）持续移动，逼着外框每帧重新模糊。
- 效果：页面静止和拖动卡片时，都没有因光斑动画引起的持续重绘。可以让光斑静止，或换成不触发背景模糊重算的实现；整体氛围不变。
- 验收：不操作页面时采样 5 秒，帧间隔稳定且无长任务；日夜两个主题的整页截图与改前观感一致。

**P3 主色调提取**
- 问题：`TinderSwipeDeck.tsx:22-78` 和 `211-213`，每张卡片挂载时用带 `crossOrigin` 的新 `Image` 把海报再请求一次，画到 canvas 读像素。
- 效果：同一张海报只提取一次并缓存；提取不阻塞卡片出现；失败时用默认色。
- 验收：来回切换同两张卡片，网络面板里每张海报的额外请求不超过 1 次。

**P4 移动中的大阴影**
- 问题：当前卡片带 `0 34px 90px` 阴影加 `0 0 70px` 光晕（`TinderSwipeDeck.tsx:277-279`），随拖动每帧重绘。
- 效果：拖动过程中减轻或暂停大范围阴影，松手后恢复；静止时外观不变。
- 验收：静止截图与改前一致；计入 P0 的改后数据。

**P5 退场依赖定时器**
- 问题：`TinderSwipeDeck.tsx:226-259` 用 `setTimeout(…, 230)` 等退场动画，与弹簧动画的实际时长无关。
- 效果：以动画完成为准切换卡片；快速连续操作不丢卡、不重复触发、不出现两张卡同时响应拖动。
- 验收：1 秒内连续操作 5 次，牌堆顺序正确，待看清单和已处理数量与操作次数一致。

**P6 一次滑动引起整页重渲染**
- 问题：上滑和下滑会更新 `App` 级状态（`App.tsx:404-421`），整页重渲染，并让 `swipeCandidateMovies`（`App.tsx:480-496`）对全部影片带 `Math.random()` 重新排序。
- 效果：牌堆交互期间，侧栏只在自己的数据变化时重渲染；候选排序在一轮内稳定，不因无关状态变化重算。
- 验收：用 React Profiler 或渲染计数确认，左右切换时侧栏不重渲染；上滑和下滑时只有受影响的部分重渲染。

**P7 图片加载**
- 效果：只加载当前、上一张、下一张的海报，下一张提前解码，切换时不出现先空白后出图。
- 验收：连续切换 10 张，没有卡片出现后再闪出海报的情况（静态缓存、正常网络下）。

### S. 随心一刷交互

**S1 操作按钮**
- 问题：底部提示（`TinderSwipeDeck.tsx:162-174`）画成键盘按键的样子，实际只是说明文字，且对比度很低。
- 效果：换成四个真实按钮：上一部、不感兴趣、加入待看、下一部。每个点击区域不小于 44×44px，有图标和文字，“加入待看”沿用珊瑚色强调。触屏和鼠标都能用。
- 验收：四个按钮的效果与对应手势完全一致；键盘 Tab 可到达，有可见的焦点样式。

**S2 键盘操作**
- 效果：牌堆可见且没有弹窗、焦点不在输入框时，← 上一部，→ 下一部，↑ 不感兴趣，↓ 加入待看，Enter 打开详情。
- 验收：五个按键生效；在搜索框或 Vibe 输入框里打字、详情弹窗打开时不触发。

**S3 方向语义统一**
- 问题：现在把卡片向左拖是“下一部”（`TinderSwipeDeck.tsx:147-148`），底部提示却写“左 上一部”。
- 效果：手势保持现状（向左甩走当前卡片进入下一部，向右拉回上一部）；按钮和键盘按 S1、S2；界面上不再出现互相矛盾的方向说明。
- 验收：按钮、键盘、手势三种方式下，“上一部”和“下一部”各自到达同一张卡片。

**S4 拖动时的方向反馈**
- 效果：向上或向下拖动超过一小段距离后，卡片上出现“不感兴趣”或“加入待看”标签，透明度随位移增加；过了触发阈值有明确变化（比如标签变实）。
- 验收：慢速拖动能看到标签渐显；没过阈值松手，卡片弹回且不触发任何操作。

**S5 操作反馈与撤销**
- 问题：加入待看和不感兴趣之后卡片直接消失，没有提示，无法反悔。
- 效果：操作后出现轻提示，例如“已加入待看 · 撤销”，约 5 秒后消失。撤销会恢复卡片位置、待看清单和类型偏好分。
- 验收：对同一张卡片执行加入待看再撤销，待看清单、`localStorage` 里的偏好分与操作前相同，卡片回到牌堆顶。

**S6 高度自适应**
- 问题：卡片固定 480 / 540 / 600px 高（`TinderSwipeDeck.tsx:125`）。
- 效果：卡片高度跟随可用视口高度，保持海报比例。
- 验收：1440×900、1280×720、375×667 三种视口下，卡片和四个按钮同时完整可见，无需滚动页面。

**S7 后台刷新会重置牌堆**
- 问题：`swipeDeckResetKey`（`App.tsx:500-503`）由整个片库的 id 拼成。片库在进入 30 秒后、之后每 180 秒后台刷新（`App.tsx:216-242`），一旦有新片加入，牌堆跳回第一张。这是从代码推断的，未复现。
- 效果：后台刷新不打断当前这一轮；只有用户主动“再来一轮”时重置。
- 验收：先写出能复现的用例（模拟片库新增一部），确认修复前会重置、修复后停在原卡片。

**S8 刷完的空态**
- 问题：`TinderSwipeDeck.tsx:99-105` 显示英文“No cards left in this round.”。
- 效果：中文说明加“再来一轮”按钮，风格与页面其他空态一致。
- 验收：把一轮刷完能看到空态，点按钮得到新一轮。

### U. 页面与内容

**U1 探索目录的“再加载 24 部”**
- 问题：`MovieSlider.tsx:171-179`。用户明确不要这个按钮。
- 效果：横向滚动接近末尾时自动接上下一批，右上角计数保留；不出现“加载更多”按钮。
- 验收：一直向右滚动能看完全部影片；页面上没有该按钮；滚动过程不跳动。

**U2 页脚的数据来源署名**
- 问题：`DataAttribution.tsx` 占一整行，用户认为是无用内容。但 TMDB API 使用条款要求展示署名和免责声明，不能删除。
- 效果：默认只留一个低调的“数据来源”入口（位置与页面右上角的小图标或页面最底部对齐均可），点开后显示 TMDB 标志、两句声明和 JustWatch 链接。
- 验收：默认状态下页脚不再占一整行；点开后原有的标志、“This product uses the TMDB API but is not endorsed or certified by TMDB.”和 JustWatch 链接都在；键盘可打开和关闭。

**U3 日间主题文字对比度**
- 效果：正文文字与其背景的对比度不低于 4.5:1，大号文字和图标不低于 3:1。需要逐处处理的至少包括：侧栏影片的类型和“最近添加”、两个空态、随心一刷的说明文字、页脚、顶部副标题。通过加深文字或给文字所在区域加一层深色半透明底来实现，不改背景渐变。
- 验收：列出每处的前景色、背景取样色和对比度数值；夜间主题不受影响。

**U4 占位预告片**
- 问题：全部影片的 `trailerUrl` 是 4 个与电影无关的素材视频之一（`server.ts:270-274`、`518`；静态缓存 316 部全是）。
- 效果：去掉所有预告片入口：详情弹窗的“观看预告片”（`MovieDetailModal.tsx:83`、`278-282`）和侧栏缩略图上的播放图标（`Sidebar.tsx:77-78`）。侧栏条目点击后仍是打开详情。
- 验收：界面上没有任何会播放占位视频的入口；因此不再被引用的文件（如 `VideoPlayerModal.tsx`）列入待删清单，等用户确认，不直接删。

**U5 详情弹窗的关闭与焦点**
- 问题：`MovieDetailModal.tsx:36-44` 只有右上角按钮能关闭。
- 效果：Esc 和点击遮罩都能关闭；打开时背景不滚动，焦点进入弹窗，关闭后回到触发它的元素。
- 验收：四种行为逐一验证；在弹窗内点“推荐相似”切换影片后，Esc 仍然有效。

**U6 评分标签写错来源**
- 问题：评分取自 TMDB 的 `vote_average`（`server.ts:501`），界面标成“IMDb”（`HeroSection.tsx:49-51`、详情弹窗）。
- 效果：改为“TMDB”或只用星标加分数，全站统一。
- 验收：全站搜不到“IMDb”字样。

**U7 中英文混排**
- 问题：详情里的“Likes”“Audio JA”（`MovieDetailModal.tsx:95`、`99`），首屏的“ZH 原音”（`HeroSection.tsx:72`），筛选面板的“原作语言 / Language”。
- 效果：统一成中文，语言代码映射成中文名（中文、英语、日语、韩语等，未知代码显示大写代码）。
- 验收：首页、详情、筛选面板里没有残留的英文界面标签（片名、平台名、专有名词除外）。

**U8 相似推荐不排序**
- 问题：`getSimilarMovies`（`movieService.ts:171-175`）取片库里前 3 部有任一相同类型的影片，《侧耳倾听》推荐了《猫和老鼠》。
- 效果：按共同类型数量降序，其次按评分降序。
- 验收：`tests/movie-service.test.ts` 加用例：共同类型更多的排在前面；同分时评分高的在前；不包含影片自身。

**U9 首屏切换箭头只在悬停时出现**
- 问题：`HeroSection.tsx:94` 的箭头 `opacity-0 group-hover:opacity-100`，触屏上看不到。
- 效果：触屏和窄屏下常显；并加一组小圆点表示当前是第几部、共几部。
- 验收：375px 宽度下能看到并点到箭头；圆点随切换变化。

**U10 筛选面板没有入口**
- 问题：`FilterPanel.tsx:49` 在未打开时直接返回空，而打开它的 `onToggle` 只在面板内部被调用；代码里没找到其他入口，线上界面也没看到。README 把“多维筛选”列为核心功能。请先确认这个判断。
- 效果：在搜索框旁或顶部工具区加一个筛选按钮，样式与右上角的小图标按钮一致；有筛选条件生效时按钮有标记。
- 验收：能打开和收起筛选面板；改变类型、年份、评分、语言、平台后探索目录随之变化；“重置”恢复全部。

**U11 永不执行的代码与假数据**
- 问题：`App.tsx` 里有多处 `{false && …}`（`647`、`754`、`784`、`801` 附近）、`className="hidden"` 的登录按钮、4 条写死的假通知（`456-461`）、恒为空的 `currentUser`（`197`）。
- 效果：移除永不执行的分支和假通知及其相关状态。`currentUser` 相关的同步代码和 `AuthModal.tsx` 保留不动（属于未启用的功能，不是本轮范围）。
- 验收：`npm run check` 通过；界面无变化。

**U12 README 与实际不符**
- 问题：README 写“账号同步”“支持键盘操作”“随心一刷用卡片手势表达喜欢、跳过”，而登录入口未启用，键盘此前只在个别地方有效。
- 效果：按本轮做完后的真实情况改写：键盘操作写清支持范围；账号同步写成“代码已具备，线上演示未启用”；功能列表与界面一致。`docs/screenshots/hooyi-desktop.png` 换成新截图。
- 验收：README 的每条功能描述都能在本地运行的界面上找到对应。

**U13 手机端走查**
- 做法：375×812 下把首页、随心一刷、Vibe、详情弹窗、待看清单、观看历史各走一遍。
- 验收：无横向滚动，文字不溢出，所有按钮点得到；发现的问题按第 2 节的风格原则修掉，并在收尾说明里列出。

## 5. 验证

- 每完成一组运行 `npm run check`（类型检查、测试、构建）。
- 性能按 P0 的方法出改前改后数据。
- 界面条目在本地浏览器逐项验证，桌面 1440×900 和手机 375×812 各一遍，日间夜间主题各一遍。
- 改前先把首页、随心一刷、详情弹窗在日夜主题下各截一张图，留作风格对比的基准。

## 6. 自审

全部做完后逐项核对，把结果写进收尾说明：

1. 第 4 节 29 项，每项的验收标准是否有对应证据（数字、测试名或截图）。没有证据的标“未验证”并写原因。
2. 风格：把改后截图与第 5 节的基准图并排，逐张确认配色、字体、圆角、玻璃质感没有变；新增的按钮、轻提示、筛选入口看起来像原本就在那里。
3. 第 2 节“不做”里的每一条是否都没碰：`git diff main --stat` 里不应出现 `server.ts` 的推荐与片库逻辑、`render.yaml`、`netlify.toml`、`.env.example`、`supabase-schema.sql`。
4. 以一个第一次打开网站的用户身份完整走一遍：进首页，筛选，打开详情，进随心一刷用按钮、键盘、手势各操作几次，撤销一次，看待看清单。记录任何卡顿、看不清、点不动、不知道下一步的地方并修掉。
5. 浏览器控制台无报错。
6. 通读 diff，删掉调试代码、采样脚本和无关改动。

## 7. 收尾

- 输出收尾说明：改了什么、P0 的改前改后数据、每项验收证据、未验证项及原因、待用户确认的删除清单、给用户的实测步骤和预期结果、如何回退（切回 `main`）。
- 停在分支上，等用户验收后再决定合并和部署。
